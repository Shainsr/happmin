# SHIN VPN

نسخهٔ بازطراحی‌شدهٔ کلاینت VPN با Flutter و هستهٔ Xray.

## تغییرات این نسخه

- نام نمایشی برنامه، کاشی Quick Settings و ویجت به **SHIN** تغییر کرد.
- آیکون لانچر و کاشی اندروید به حرف سفید **S** روی زمینهٔ تیره تغییر کرد.
- اندازهٔ نوشته‌های اصلی کارت سرورها دو واحد کاهش یافت.
- دکمهٔ اتصال افکت نئونی دارد و موج‌های اتصال/قطع با محوشدن نرم تغییر می‌کنند.
- ویجت و Quick Settings بدون بازکردن Activity فرمان را اجرا می‌کنند. فقط در اولین استفاده، اگر مجوز VPN اندروید هنوز صادر نشده باشد، سیستم باید صفحهٔ مجوز را نمایش دهد.
- وضعیت اتصال از callback واقعی هسته به ویجت و کاشی منعکس می‌شود؛ دیگر قبل از اجرای فرمان به‌صورت حدسی تغییر نمی‌کند.
- RTT اصلی از سه handshake واقعی TCP به endpoint سرور اندازه‌گیری و مقدار میانه نمایش داده می‌شود. DNS خارج از زمان‌سنجی است. این مقدار ICMP ping نیست و تأخیر کامل تونل را هم نشان نمی‌دهد.
- TCP تک‌نمونه برای مقایسه در کنار RTT میانه باقی مانده است.
- ارسال درخواست سازنده فقط با وب‌هوک HTTPS معتبر فعال می‌شود. آدرس وب‌هوک در `lib/main.dart` در `kCreatorWebhookUrl` قرار می‌گیرد. اگر وب‌هوک تنظیم نشده باشد، متن درخواست در کلیپ‌بورد کپی می‌شود؛ در این حالت درخواست خودکار به سازنده نمی‌رسد.
- توکن محرمانهٔ ربات تلگرام داخل APK قرار نمی‌گیرد؛ قرار دادن آن در برنامهٔ کلاینت امکان استخراج و سوءاستفاده دارد.

## ساخت

از ریشهٔ پروژه:

```bash
flutter pub get
flutter analyze
flutter build apk --release --split-per-abi
```

## تنظیم دریافت درخواست سرور

یک endpoint سمت سرور با HTTPS معتبر بسازید و URL آن را در `kCreatorWebhookUrl` قرار دهید. endpoint درخواست JSON شامل `app`, `version`, `hwid`, `note` و `timestamp` را دریافت می‌کند. endpoint باید درخواست را احراز هویت و محدودسازی نرخ کند؛ برای استفادهٔ عمومی بهتر است یک توکن کوتاه‌عمر یا امضای سمت سرور اضافه شود و هیچ راز ثابتی داخل APK قرار نگیرد.

## نکته دربارهٔ پینگ

RTT نمایش‌داده‌شده، زمان handshake اتصال TCP به IP/Port سرور است؛ زمان DNS در آن محاسبه نمی‌شود و میانهٔ سه تلاش است. این معیار برای مقایسهٔ مسیر شبکه به endpoint مناسب است، اما با ICMP ping یا تأخیر درخواست HTTP از داخل تونل یکسان نیست. بنابراین عدد ۱۰۰ تا ۲۰۰ میلی‌ثانیه فقط در صورتی به دست می‌آید که مسیر TCP واقعاً چنین تأخیری داشته باشد؛ عددی به‌صورت مصنوعی کم نمی‌شود.
